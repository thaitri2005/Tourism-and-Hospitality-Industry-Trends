# Crawling-method and blocked-source recheck — 12 October 2026

## Result

The useful newer pattern is **index-first discovery with a conventional, auditable crawler**. Tools such as Crawl4AI offer browser rendering, structured extraction and site scans using sitemaps, home-page links, Common Crawl and (in full mode) Wayback indexes. Crawlee offers persistent request queues, retries and browser support. These features help discover pages, handle JavaScript and recover work. Under the user's reported permission for public material, this project records a CTO/Travel Weekly 403 as a denial of that URL, then continues to other independent configured public routes without attempting to defeat the denied URL.

I applied an index-first public-web investigation to the three unresolved sources. It found better official archive leads for CTO and Travel Weekly than are represented in the local queue, but **did not add records to the corpus**: the direct collector previously received 403 from sitemap URLs, and the web search/index view is not a reproducible bulk export. IH&RA's official site and sitemap are crawlable, but the newly checked newsroom evidence remains predominantly pre-study-window.

## Tool update

The normal archive-history walker now includes the official CTO News, Travel Weekly Travel News and IH&RA newsroom routes. It follows same-host next/older links within each configured collection, saves each page's URL queue and cursor together, detects repeated article sets, and stops at 250 pages per source per invocation before resuming on the next run. It uses the shared HTTP client, so it retains robots checks, three-second minimum spacing, retry deadlines and same-host redirect checks. A denied URL is logged and skipped; browser disguise, proxy rotation and challenge solving are not used.

### Robots endpoint 403 handling

The [IETF Robots Exclusion Protocol standard, RFC 9309 §2.3.1.3](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.3.1.3), defines 4xx responses for `robots.txt` as “unavailable.” The user reports permission that supersedes robots directives for this academic collection, so CTO and Travel Weekly robots responses are recorded but their allow/disallow rules are not applied. The ordinary identifiable user agent, same-host checks, and minimum three-second spacing remain active. If a sitemap, archive, article or PDF returns 403, that URL is recorded and skipped; other configured public routes continue. A 401 remains a source hold; 429 triggers cooldown. Denied URLs are not retried.

This is an implementation change only. The saved snapshot predates URL-local 403 handling, so it does not show whether other CTO or Travel Weekly routes will respond successfully. Run `python run_research.py` to migrate the saved 403 holds and resume all configured routes. IH&RA's accessible archive still needs in-window article evidence before it can contribute to the 2016–2026 analysis.

## Method assessment

1. **Use an index to find routes, not to declare coverage.** The official CTO date/category archives are strong new discovery leads. Travel Weekly search results prove that dated articles exist in the target period, but a few hand-found pages do not constitute a historical sample.
2. **Fetch and verify from the publisher when allowed.** Preserve the canonical URL, source, date evidence, retrieval time, response status and archive provenance. Keep the project's existing per-URL commit/checkpoint/retry flow for actual ingestion.
3. **Continue across independent public URLs.** Under the user-reported authorization, a CTO or Travel Weekly URL returning 403 is recorded and skipped; the crawler continues to other configured sitemaps and public archive/article URLs at the normal slow rate. It does not retry the denied URL, disguise the client, use proxies, or authenticate. A 401 remains a source hold; a 429 invokes cooldown. A sitemap denial therefore does not suppress unrelated archive routes.
4. **Treat browser rendering as a format fix, not an access fix.** A headless browser is valuable when the publisher page is permitted but its article links/text load through JavaScript. It should not be used with stealth, rotating identities, proxy routing or other methods to defeat a 403 or robots restriction.
5. **Use Common Crawl/Wayback as a separate archival lead or research collection.** Common Crawl's [URL Index](https://www.commoncrawl.org/url-index) describes a public URL-to-WARC index; its [getting-started guide](https://commoncrawl.org/get-started) documents lookup and retrieval. An archive capture has a different retrieval date/source provenance and may have missing or partial content. It must be labelled separately, assessed under applicable terms, and never silently represented as a current first-party fetch. The direct Common Crawl API probe could not run from this restricted workspace network; no index results are claimed here.
6. **Do not pay for or add a hosted scraper just for these failures.** Crawl4AI's [official docs](https://docs.crawl4ai.com/) describe both open-source browser crawling and a hosted API; the hosted service requires an API key and may not resolve a publisher block. No API key/service was used. Crawlee's [official retry options](https://crawlee.dev/js/api/3.10/basic-crawler/interface/BasicCrawlerOptions) improve queue and retry behavior, which this project already implements, but do not address denied robots access.
